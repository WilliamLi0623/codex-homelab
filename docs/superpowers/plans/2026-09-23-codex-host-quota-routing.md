# Codex Host Quota Routing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Route local and reachable remote Codex main sessions and subagents to Luna/High normally, then Spark/xhigh for the main role and GLM/MAX for subagents only when the Codex account quota is authoritatively exhausted.

**Architecture:** Use the supported Codex app-server account rate-limit read as the quota source and preserve one Codex conversation when switching providers if the installed app-server supports it. Keep Spark on CC Hub Responses; expose GLM Chat Completions to Codex subagents through a loopback-only Responses adapter. Controller synchronization is defined in `2026-09-23-homelab-worker-role-routing.md` and is a required integration dependency.

**Tech Stack:** Codex CLI/app-server JSON-RPC, Go, Responses SSE, CC Hub Chat Completions, TOML user configuration.

**Spec:** `docs/superpowers/specs/2026-09-23-fixed-codex-role-routing-design.md`

## Global Constraints

- Normal main session, subagent, and Proxmox/K3s worker are `gpt-6-luna` with reasoning `high`.
- On authoritative Codex account quota exhaustion, main is `muse-spark-1.3-contributor` with `xhigh`; subagents and Proxmox/K3s worker are `glm-5.3-flash` with `max`.
- Switch back only on an authoritative quota recovery signal; do not infer quota state from generic HTTP status, usage percentages, or reset timestamps.
- Keep the direct OpenAI provider path and existing CC Hub secret source; never persist or log key values.
- GLM uses Chat Completions; Spark and direct OpenAI use Responses.
- Do not restart Codex implicitly, replay active turns, or alter already-running subagents.
- Preserve unrelated `config.toml` providers, profiles, MCP servers, hooks, and approval/sandbox settings.
- Bind any local adapter only to `127.0.0.1`; never default to `0.0.0.0`.

### Task 3: Implement the host quota-state coordinator

**Files:**
- Create: `internal/codexrouting/quota.go`
- Create: `internal/codexrouting/appserver_client.go`
- Create: `internal/codexrouting/state_sink.go`
- Create: `internal/codexrouting/coordinator.go`
- Create: `cmd/codex-routing-agent/main.go`
- Test: `internal/codexrouting/*_test.go`

**Interfaces:**
- `QuotaReader.Read(ctx) (QuotaSnapshot, error)` calls only the installed app-server `account/rateLimits/read` RPC.
- `QuotaSnapshot` contains `OrdinaryUsageAllowed`, `RateLimitReachedType`, primary/secondary reset instants, and a local observation time; it never retains account IDs or reset-credit identifiers.
- `ClassifyQuota(snapshot)` returns `normal`, `quota_fallback`, or `unknown`. Only explicit exhausted-state fields produce `quota_fallback`; `unknown` preserves the current state.
- `ModeSink.Set(ctx, mode, observedAt, generation)` sends the state to the authenticated Controller endpoint defined in the worker plan; generation is a persisted monotonic host-side counter incremented on each authoritative transition. It sends no prompt, thread history, account ID, or provider secret.

- [x] Add table-driven tests proving explicit exhausted signals select fallback; true recovery selects normal; missing fields, transient query errors, HTTP 429/503, auth errors, and percentages below 100% do not guess a transition.
- [x] Add mocked app-server RPC tests for JSON-RPC framing, timeout, cancellation, malformed response, and credential-redacted errors.
- [x] Implement bounded polling with one in-flight read, cancellation on shutdown, and transition-only updates; avoid continuous state writes when the state is unchanged.
- [x] Implement an idempotent authenticated mode update using the worker plan's request contract, persist the monotonic transition generation across coordinator restarts, and reject stale observations/generations at the receiving Controller.
- [x] Verify that monitor restart reads current authoritative state before publishing and does not default an unavailable read to normal or fallback.

Run: `go test ./internal/codexrouting -count=1`

Expected: state transitions are deterministic and only authoritative; no secrets or account identifiers are serialized.
