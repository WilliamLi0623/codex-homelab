The five previously destroyed dynamic workers had no remaining PVE
configuration and no Pod/Job, but their stale `NotReady` Node objects were
still present in K3s. The exact Node names for VMIDs 3001, 3002, 3003, 3007,
and 3008 were deleted and rechecked after a delay; none re-registered.

The Controller release boundary is now quiescent before Node deletion:
`VERIFY_IDENTITY` and idempotent Proxmox `STOP` execute inside the

`VERIFY_NODE_REMOVED` checkpoint. The successful completion path also cancels

not confirmed. This closes the observed k3s-agent re-registration race while
preserving existing durable release-step names and recovery semantics.

At this checkpoint, new dynamic nodes did not yet inherit the local OCI worker
image without an explicit per-node import. The follow-up below records how
that blocker was later resolved for the tested template path.
